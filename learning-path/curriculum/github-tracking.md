# Suivi GitHub et fonctionnement de la cohorte
Issue centrale #45; Labs #14–21, contributions #36–42, Meetups #22–26, offres #27–35. Réutiliser ces issues pour travail collectif, pas de duplication de labs.
## Flux
- Responsable pédagogique nomme mentors, évaluateurs et fixe dates réelles; inscrit cohorte de 2–4 volontaires en registre privé.
- Une issue hebdomadaire collective S01–S12 est créée seulement après vérification des doublons, avec thème, lien au programme, objectif, livrable et jalon. Chaque semaine : plan → cours → exercices → TP via branche/PR → revue → reproduction → bilan.
- Branches proposées : training/sXX/<sujet-synthetique>; PR lie issue de semaine et lab, contient test attendu/réel, version, licence, rollback, nettoyage, revue. Pas de nom candidat ou note en public sans autorisation.
- Statuts : À faire / En cours / Bloqué / En revue / Validé (pédagogique); validation de lab exige ses critères, validation de certification exige jury. Ne pas fermer un lab global sur la seule progression d'un candidat.
- Portfolios individuels, scores, PV et preuves client dans espace privé habilité; [modèle](../portfolio-template.md). Le dépôt public n'héberge que supports et artefacts synthétiques.

## Bilan hebdomadaire (modèle)
Semaine / objectifs / cours réalisés / exercices et tests / lab et PR / résultat attendu-réel / compétences travaillées / contribution (état réel) / risque ou blocage / action suivante / revue mentor. Note individuelle en privé.
## Pilotage
Réunion hebdomadaire 30 min : avancement, blocages, capacité, plan correctif. KPI agrégés sans identification : labs validés, PR revues, taux de critères atteints, contributions soumises/acceptées/fusionnées distinctes, incidents et délais, rétention; ne pas inventer de résultats. Aucune vente exigée. Revue finale et REX, recalibrage par PR.
